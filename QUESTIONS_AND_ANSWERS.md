# Вопросы и ответы для защиты проекта CSMA Simulator

## 1. Общие вопросы о проекте

### В: Что делает эта программа?
**О:** Программа симулирует работу сети CSMA (Carrier Sense Multiple Access) — протокола доступа к общему каналу передачи данных. Она моделирует N хостов, которые генерируют пакеты и пытаются передавать их по одному общему каналу, соблюдая правила CSMA. Программа вычисляет различные метрики производительности сети.

### В: Какие параметры принимает программа?
**О:** 
- `--N` - количество хостов в сети
- `--alpha` - интенсивность прибытия пакетов (пакеты/сек)
- `--simtime` - время симуляции (сек)
- `--B` - пропускная способность канала (Мбит/сек)
- `--L` - дли��а канала (м)
- `--l` - размер пакета (байты)
- `--qlimit` - максимальный размер очереди (-1 = неограниченная)
- `--csv` - имя файла для сохранения результатов

### В: Какие метрики вычисляет программа?
**О:**
1. **lost_fraction** - доля потерянных пакетов (отброшенные / созданные)
2. **avg_attempts** - среднее количество попыток передачи на пакет
3. **avg_queue_len** - средняя длина очереди для каждого хоста
4. **max_queue_len** - максимальная длина очереди
5. **channel_util** - утилизация канала (время занятости / общее время)

## 2. Архитектура и структуры данных

### В: Какие структуры данных используются в программе?
**О:**
- **Packet** - представляет пакет с ID, хостом-отправителем, временем прибытия и количеством попыток
- **Event** - представляет событие в симуляции (время, тип, хост, ID пакета)
- **EventComp** - компаратор д��я приоритетной очереди событий
- **priority_queue** - очередь событий, отсортированная по времени
- **deque** - очередь пакетов для каждого хоста

### В: Почему используется priority_queue для событий?
**О:** Priority_queue позволяет эффективно (за O(log n)) извлекать событие с наименьшим временем. Это критично для дискретно-событийной симуляции, где события должны обрабатываться в хронологическом порядке.

### В: Как работает EventComp компаратор?
**О:** EventComp использует оператор `>` вместо `<`, потому что priority_queue в C++ — это max-heap по умолчанию. Инвертируя сравнение, мы получаем min-heap, где события с меньшим временем находятся на вершине. Если времена равны, события сортируются по типу (EVT_ARRIVAL раньше EVT_TX_END).

## 3. Вычисления и формулы

### В: Как вычисляется время передачи пакета?
**О:** 
```
tx_time = (l_bytes * 8) / (B * 1e6)
```
Где:
- `l_bytes * 8` - размер пакета в битах
- `B * 1e6` - пропускная способность в бит/сек (B задана в Мбит/сек)
- Результат в секундах

Пример: пакет 1500 байт при 100 Мбит/сек = 12000 бит / 100e6 бит/сек = 0.00012 сек

### В: Как вычисляется задержка распространения?
**О:**
```
prop_delay = L / 2e8
```
Где:
- `L` - длина канала в метрах
- `2e8` - скорость света в медном кабеле (примерно 2/3 от скорости света в вакууме)
- Результат в секундах

Это время, за которое сигнал распространяется от одного конца канала к другому.

### В: Как вычисляется средняя длина очереди?
**О:** Используется метод трапеций (численное интегрирование):
```
queue_time_area[i] = сумма(длина_очереди[i] * dt)
avg_queue_len[i] = queue_time_area[i] / simTime
```
Мы накапливаем площадь под графиком длины очереди, а затем делим на общее время с��муляции.

### В: Как вычисляется утилизация канала?
**О:**
```
channel_util = cumulative_channel_busy / simTime
```
Это отношение времени, когда канал был занят, к общему времени симуляции. Значение от 0 до 1 (или 0% до 100%).

## 4. Логика симуляции

### В: Как работает основной цикл симуляции?
**О:** 
1. Извлекаем событие с наименьшим временем из очереди
2. Обновляем текущее время симуляции
3. Обновляем статистику очередей (интегрируем длину)
4. Обрабатываем событие (прибытие или конец передачи)
5. Повторяем, пока очередь не пуста или время не превышено

### В: Что происходит при событии EVT_ARRIVAL?
**О:**
1. Создаем новый пакет и увеличиваем счетчик
2. Проверяем, есть ли пакеты в очередях других хостов
3. Если канал свободен, нет ожидающих пакетов и своя очередь пуста → передаем сразу
4. ��наче добавляем пакет в очередь (или отбрасываем, если очередь переполнена)
5. Генерируем следующее событие прибытия для этого хоста

### В: Что происходит при событии EVT_TX_END?
**О:**
1. Обновляем время занятости канала
2. Увеличиваем счетчик переданных пакетов
3. Ищем пакет с наименьшим временем прибытия (FIFO)
4. Если найден → начинаем его передачу, планируем EVT_TX_END
5. Если не найден → канал становится свободным

### В: Почему проверяется somebody_waiting?
**О:** Это обеспечивает справедливое распределение канала между хостами. Если в других очередях есть ожидающие пакеты, новый пакет не передается сразу, а добавляется в очередь. Это предотвращает голодание (starvation) пакетов от других хостов.

### В: Как выбирается следующи�� пакет для передачи?
**О:** Используется FIFO (First In First Out) принцип: выбирается пакет с наименьшим временем прибытия среди всех очередей. Это справедливо и предотвращает голодание пакетов.

## 5. Обработка очередей

### В: Почему используется deque для очередей пакетов?
**О:** Deque (double-ended queue) позволяет эффективно добавлять элементы в конец (push_back) и удалять из начала (pop_front), что идеально для FIFO очереди. Операции выполняются за O(1).

### В: Как работает ограничение размера очереди (qlimit)?
**О:**
- Если `qlimit < 0` - очередь неограниченная
- Если `qlimit >= 0` - максимальный размер очереди равен qlimit
- Если очередь переполнена, новый пакет отбрасывается и увеличивается счетчик потерь

### В: Как обновляется статистика очередей?
**О:** Перед обработкой каждого события:
1. Вычисляем время, прошедшее с последнего события: `dt = now - last_queue_change_time[i]`
2. Добавляем площадь прямоугольника: `queue_time_area[i] += queues[i].size() * dt`
3. Обновляем время последнего события: `last_queue_change_time[i] = now`

Это позволяет точно вычислить интеграл длины очереди по времени.

## 6. Генерация случайных чисел

### В: Какое распределение используется для прибытия пакетов?
**О:** Экспоненциальное распределение с параметром `alpha`. Это означает, что интервалы между прибытиями пакетов распределены экспоненциально, что моделирует реальный трафик в сетях.

### В: Как генерируются случайные числа?
**О:**
```cpp
std::random_device rd;
std::mt19937_64 gen(rd());
std::exponential_distribution<double> exp_dist(alpha);
```
- `random_device` - инициализирует генератор случайным зерном
- `mt19937_64` - Mersenne Twister генератор (64-бит версия)
- `exponential_distribution` - экспоненциальное распределение с параметром alpha

### В: Почему используется mt19937_64 вместо rand()?
**О:** mt19937_64 имеет намного лучшие статистические свойства, больший период (2^19937-1) и не имеет проблем с младшими битами, которые есть у rand(). Это стандарт для современного C++.

## 8. Сложные моменты и оптимизации

### В: Почему пакет передается сразу, если канал свободен?
**О:** Это оптимизация для минимизации задержки. Если нет ожидающих пакетов, нет смысла добавлять пакет в очередь — лучше передать его сразу. Это также более реалистично моделирует поведение реальных сетей.

### В: Как обрабатывается конец симуляции?
**О:**
1. После основного цикла добавляем оставшееся время в статистику очередей
2. Если канал был занят в конце симуляции, добавляем оставшееся время занятости
3. Это обеспечивает точность вычисления метрик

### В: Почему используется uint64_t для ID пакетов?
**О:** Это гарантирует, что ID пакетов не переполнятся даже при очень длительных симуляциях с высокой интенсивностью прибытия. 64-бит целое число может хранить значения до 2^64-1 ≈ 1.8e19.

### В: Как обрабатываются события с одинаковым временем?
**О:** EventComp компаратор сортирует их по типу: EVT_ARRIVAL (0) идет раньше EVT_TX_END (1). Это логично, потому что сначала должны обработаться прибытия, а потом концы передач.

## 12. Теоретические основы

### В: Что такое CSMA?
**О:** CSMA (Carrier Sense Multiple Access) — это протокол доступа к общему каналу, где каждый хост перед передачей проверяет, свободен ли канал. Если канал занят, хост ждет. Это предотвращает коллизии (в идеальном случае) и обеспечивает справедливое распределение канала.

### В: Какие варианты CSMA существуют?
**О:**
- **CSMA/CD** (Collision Detection) - используется в Ethernet, обнаруживает коллизии
- **CSMA/CA** (Collision Avoidance) - используется в Wi-Fi, избегает коллизий
- **CSMA/CR** (Collision Resolution) - разрешает коллизии с помощью backoff

### В: Как CSMA отличается от других протоколов?
**О:**
- **TDMA** (Time Division) - канал разделен по времени
- **FDMA** (Frequency Division) - канал разделен по частоте
- **CDMA** (Code Division) - канал разделен по кодам
- **CSMA** - динамический доступ, основанный на ��остоянии канала

## 13. Производительность и сложность

### В: Какова временная сложность основного цикла?
**О:** O(n * m * log m), где:
- n - количество событий в симуляции
- m - количество хостов
- log m - сложность операций с priority_queue

Для каждого события мы проходим по всем хостам (O(m)) и выполняем операции с очередью (O(log m)).

### В: Какова пространственная сложность?
**О:** O(n + m * q), где:
- n - количество событий в очереди
- m - количество хостов
- q - средний размер очереди пакетов

В худшем случае это O(n + m * n), если все пакеты накапливаются в очередях.

### В: Как оптимизировать программу?
**О:**
1. Использовать более эффективные структуры данных (например, heap вместо priority_queue)
2. Кэшировать результаты поиска лучшего хоста
3. Использовать параллелизм для независимых симуляций
4. Оптимизировать компилятор флагами (-O3)

## 15. Возможные крити��еские вопросы

### В: Почему программа не моделирует коллизии?
**О:** Текущая версия предполагает идеальный CSMA без коллизий. Это упрощение, которое позволяет сосредоточиться на основной логике. Добавление коллизий потребует:
1. Моделирования одновременной передачи от нескольких хостов
2. Обнаружения коллизий
3. Реализации backoff алгоритма
Это значительно усложнит код, но может быть добавлено в будущих версиях.

### В: Почему используется экспоненциальное распределение?
**О:** Экспоненциальное распределение хорошо моделирует реальный трафик в сетях. Оно имеет свойство "без памяти" (memoryless), что означает, что вероятность следующего события не зависит от прошлого. Это реалистично для независимых источников трафика.

### В: Как программа обрабатыв��ет очень длительные симуляции?
**О:** 
1. Используется uint64_t для счетчиков (не переполнится)
2. Используется double для времени (достаточная точность)
3. Статистика вычисляется инкрементально (не требует хранения всех событий)
4. Результаты сохраняются в CSV для анализа

### В: Почему не используется параллелизм?
**О:** Основной цикл симуляции зависит от времени и состояния канала, поэтому его сложно распараллелить. Однако можно запускать несколько независимых симуляций параллельно с разными параметрами.
